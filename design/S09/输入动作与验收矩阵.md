# S09-01 输入动作与验收矩阵

日期：2026-10-25。执行依据为完整施工计划S09-01；仅本项，S09其余六项继续待做。版本0.9.1，存档根版本及原存储键不变。

## 一句话的处理顺序

1. 有明确重生披露时先留在玩家草稿，单独确认；混有提问或安排也不能先交给角色。
2. 当前选项的完整原句先对应原选项ID，避免把选项标签里的逗号拆坏。
3. 逐子句区分咨询、聊天、饮茶偏好、明确边界和动作。整句假设没有执行候选；混合句中的提问不取消另一个明确命令。
4. 本地识别原事件、活动表单及项目管理所用动作。AI只按过滤后的合法目录选候选ID，并提供原句来源；解析不能结算游戏。
5. 金额、库存、人物解锁与日程、周格、预算、双方意愿和关系阶段交原引擎预览。至多三个子行动；任一部分缺项、违例或未识别命令均先澄清，整组不执行。
6. 明确偏好和拒绝分别记录；候选须核对后提交。取消候选不撤回已表达的分寸。旧正文、流水与记忆来源不回写。

## 动作覆盖

| 输入 | 对应原动作 | 缺项或规则检查 |
| --- | --- | --- |
| 当前选项完整标签 | event，原eventId／choiceId | 日期、前置及费用仍校验；不跳到别的事件 |
| G04先拨一半，派张廷玉核账 | event G04 custom，金额6 | 承办C28／C26／C32，金额0至12，知情范围与押运；重复金额先问 |
| 当前关系节点“改日再谈” | defer，当前eventId | 原节点能否延期；不把延期当已完成 |
| 明日晚间陪你散步 | week-plan walk | 明确日期和时段；“你”为当前人物，原日程和地点照检 |
| 明日日间与苏培盛私聊／写信／见面 | week-plan chat／letter／meet | 人物姓名或“与你”；通信照原驿程，不提前收到回复 |
| 明日日间独自学习／习武／休养 | week-plan study／training／rest | 原六格；练习默认值与表单一致 |
| 明日日间备制铜制暖手炉 | week-plan craft | 清单样式GF02、原预算；实际制作后才得到物品 |
| 后日晚间送铜制暖手炉给苏培盛 | week-plan gift | 手中实际未预占库存；零件或多件同名均不擅选 |
| 明日日间宴请苏培盛和宜修 | week-plan banquet | 两至三宾客、日间起、同日两格；主题默认诗曲小宴，与表单一致，可明说清茶／时令家宴 |
| 明日晚间与你牵手／拥抱／同游／夜谈／留宿 | week-plan bond | 真实双方意愿、阶段及待补谈事项；含糊“恩爱”先问具体方式 |
| 把与你的散步改到后日晚间／取消与你的散步 | week-edit／week-cancel | 只能定位一份可变更原约；多个同类原约请从日程页明确选择 |
| 暂缓／复办／亲核／补做＋完整项目名 | 原project-* | 原项目状态、并行上限、周决策、钱款与工期 |
| 指明某人承办＋完整项目名 | project-assign | 必须明确且符合该项目承办名单，不默用默认人 |
| 单句不爱浓茶／仅合作／暂缓感情／终止恋爱 | 原savePreference／setBoundary | 当前人物与原消息来源；不改变对方意愿 |

普通话题默认“问问近况／先听对方说完”，可说“共同旧事”“心事”“眼前差事”“我也说自己的想法”；散步可指定长廊。确认页显示所识别的话题、地点与主题。未开放的官职、处分、新物和世界结果不能由模型补造。

## 缺项接续与边界

单个未完活动在同一页面会话、同一进度、人物与事件下，可补时段、日期、姓名或礼物全名。例如“与你散步”→问日期时段→“明晚”；“明日日间小宴”→问宾客→“苏培盛和宜修”。下一次若是新问题或完整新活动则不套用旧草稿。

这份短期草稿不写入存档，也不是S09-04长期摘要。刷新、换人物或场景后须重说；一组多活动有缺项时，应把完整安排分句再说。不识别“下周三”“随便挑一件”等含混日期或物品；不因此自动定日、送礼或发展关系。

季度旧档继续用原promise动作；周制使用week-plan。当前输入覆盖原规则已开放的候选，未声称支持全部自然语言表达。固定兜底答复的针对性及普通无代价对白确认分流按S09-02，真实模型语义表现仍未验收。
