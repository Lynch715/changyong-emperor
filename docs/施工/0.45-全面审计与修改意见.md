# 《重生长雍帝王赋》v0.44.1 全面审计 · 给 Codex 的修改指令

审计日期：2026-11-02　审计范围：`src/`、`index.html`、`server.mjs`、`scripts/`、`tests/`、`assets/`、README，以及 375–390px 手机实机试玩（新开局→元年正月月末）和 3 组 72 个月、1 组 30 年的无头模拟。

---

## 给 Codex 的总原则（每一项都必须遵守）

1. **本轮不新增任何玩法系统。** 只修错、减负、做清楚。凡是“再加一个机制来平衡”的冲动，一律改为删减或合并。
2. **旧存档必须能继续读。** 只允许在 `load()` 链里补字段，不允许重置进度。每项改动都加一条旧档兼容测试。
3. **玩家看到的每一句话都要能直接读懂。** 不出现“稳态”“回归”“排期”“增益”这类后台词；数字后面写清是什么。
4. **新代码禁止写成一行几百字的函数。** 单行不超过 160 字符；新函数要有一行中文注释说明它做什么。
5. 每个任务完成后跑 `npm test`，全部通过再做下一项；最后升版本号到 0.45.0，README 只写本版改动摘要。
6. 改动按下面的编号分提交，提交信息写编号，例如 `fix(A2): 打开折匣不再扣时辰`。

## A. 必修缺陷（P0，先做）

### A1 本地服务器的每日调用上限失效
- **问题**：`server.mjs` 里写的是 `calls>=Math.max(config.limit,1000)`，所以 `.env` 里设 `AI_DAILY_LIMIT=100` 实际仍是 1000，上限设置等于没用，会多花 API 钱。
- **改法**：改成 `calls>=Math.max(1,config.limit)`。
- **验收**：在 `tests/server.test.mjs` 增加用例：limit=2 时第 3 次请求返回 429。

### A2 点开“批折”就扣一个时辰
- **问题**：首页“批折 · 3”直接进入审阅并扣掉 1 个时辰，即使一道都没批。实测打开两次、一道未批，当月只剩 1 个时辰。玩家只是想看看折子写什么，就白白丢掉一个行动。
- **改法**：打开折匣只浏览、不扣时辰；**第一次落笔（准/驳/交部议/留中/查核）时**才扣 1 个时辰，并在顶部显示“本时辰还可批 N 道”。合上折匣后，同一时辰内重新打开不再扣。
- **验收**：新测试：打开→合上→`s.ap` 不变；打开→批一道→`s.ap` 减 1；同一时辰再开再批不再扣。

### A3 折匣规则说明前后矛盾
- **问题**：README 写“一个时辰最多批三道，设值房后五道”；游戏内写“一时辰通常可批六道；设值房后可批十道”。
- **改法**：以代码实际数值为准，统一 README 和界面文案。界面文案压缩成一句：“一个时辰可批 N 道（设值房后 M 道）。”
- **验收**：`grep` 全仓库不再出现另一套数字。

### A4 线上版本缓存不更新
- **问题**：`index.html` 里的样式写的是 `v2.css?v=0.42.0`，版本早已到 0.44.1；JS 模块完全没有版本参数。手机浏览器很可能还在用旧代码，配合新存档字段会出错。
- **改法**：`scripts/build-pages.mjs` 构建时把 `index.html` 中的 `?v=…` 替换为 `package.json` 的版本号；`main.js` 的入口也加 `?v=版本`（模块内部 import 不必逐个改，入口变化即可让浏览器重新取）。
- **验收**：`tests/release.test.mjs` 断言 `_site/index.html` 中 css 和入口 js 都带当前版本号。

### A5 Pages 发布了 170MB 用不到的原图
- **问题**：`assets/` 根目录 81 张 PNG/JPG 原稿（约 171MB）运行时从不引用（游戏只用 `assets/exports/s11-v1/` 下的导出图），但 `build-pages.mjs` 整个复制 `assets/`，线上包约 258MB。
- **改法**：
  1. 构建只复制 `assets/exports/s11-v1/` 和 `assets/fonts/`。
  2. 【作者已定：移出仓库】把根目录原稿移到 `art-source/`，并把 `art-source/` 加入 `.gitignore`；用 `git rm --cached` 让它们不再被跟踪。**只从 Git 中移除，本机文件必须保留，不要删除原稿。**导出脚本（`scripts/export-*.py/mjs`）的读取路径同步改到 `art-source/`。不改写 Git 历史。
  3. `exports/s11-v1` 内同一张图同时有 png/jpg/webp 多份：只发布代码实际引用的格式。
- **验收**：在 release 测试里扫描 `src/v2/*.js` 引用的所有 `assets/…` 路径，断言 `_site` 中每个引用都存在、且 `_site/assets` 总大小 < 90MB。

### A6 仓库杂物
- 根目录 `.chk.mjs` 是一段临时检查脚本：把其中 6 个用例并入 `tests/`（皇嗣过滤测试），然后删除该文件。
- `123.env` 文件名不规范：README 和 `npm start` 只保留 `.env`，`123.env` 作为兼容读取可留一版，但文档里不再推荐。
- `release.test.mjs` 在“不能删除文件”的环境里会因 `_site/.nojekyll` 失败：构建脚本先 `rm` 再写时，若 `EPERM` 则改为覆盖写入，不要整个失败。

## B. 开局与主循环（P1，影响“好不好玩”）

### B1 正月开局太慢，三场都是苏培盛
- **问题**：新开一局，正月必须连续处理「养心惊梦」「留茶夜谈」「留茶」三场苏培盛戏，标题还重复，玩家要到第 4 个画面才第一次能自由行动。
- **改法（作者已澄清）**：
  1. 正月必做要事只有「养心惊梦」，做完即可自由行动。
  2. 「留茶夜谈」和「留茶」合并为一场，只保留一个标题；挪到二月或正月夜里选苏培盛时，取改动较小的方案。
  3. 正月另加可选朝政小事，不占要事位、不挡行动、不耗时辰；首页醒目卡片放在行动按钮上方，结果明确列出至少两类数值变化。
  4. 当月不处理就于月末撤下，无惩罚、不顺延；已过正月的旧档不补发。
- **验收**：新开局完成「养心惊梦」后六个行动按钮都可用；不办朝政小事也能入夜、结束本月；办过后正月月末报告至少两类数值变化；补对应旧档和流程测试。

### B2 首页信息过载
- **问题**：首屏依次是：六项数值、要事提示、卷名、户部银账（月底常例/地方浮动/经营进项/军政/新政预留……）、要事卡，行动按钮在第一屏底部才露出。下面还有派系声势、盛世还须、御览密折、局势、奏报回报、要务。第一个月就看到“新政预留最多 0 万两”“十省平均吏治达到 60”，对新玩家是“天书”。
- **改法**（只改呈现，不改数值）：
  1. 首页顺序固定为：**顶部数值 → 本月要事卡 → 六个行动按钮 → 入夜 → 身边的人**。
  2. 户部银账卡收进“理财”页，首页只留一行：“本月进 X · 出 Y · 月底预计 Z 万两”。
  3. 派系声势、盛世条件、密折、地方、奏报合并成一个折叠区“朝局详情 ›”，默认收起。
  4. 第一年隐藏“新政预留”“经营进项”等当年不可能用到的字段（值为 0 且系统未解锁时不显示）。
- **验收**：390×844 视口下，新开局首屏不滚动即可看到要事卡和全部六个行动按钮（截图存 `output/playwright/v045/home.png`）。

### B3 情分数字显示易误读
- **问题**：人物卡显示“相识 · 34+4”，看起来像算式。
- **改法**：改为“相识 · 34（本月 +4）”，增量用小号绿色/红色。

### B4 原生 `confirm()` 弹窗
- **问题**：“还有 N 个时辰没用，确定入夜吗？”用的是浏览器原生 `confirm`，手机上样式突兀，部分内嵌浏览器会直接屏蔽。
- **改法**：用页面里已有的 `<dialog id="modal">` 做同样的确认框，两个按钮“再忙一会儿 / 入夜”。全仓库 `confirm(` 一并替换。

### B5 成就弹层
- **问题**：成就弹层（`.cele.ach-pop`）刷新页面后会再次出现，需要再点一次。
- **改法**：弹出即从 `s.cele` 中移除并存档；同一成就不重复弹。

## C. 数值与节奏（P1–P2）

以下结论来自无头模拟（随机选项、每月 3 个行动以赏赐/休养为主、夜里随机一人，3 个种子 × 72 个月，另 1 局跑到第 7 年）。

### C1 国库只进不出，后期毫无压力
- **现象**：不刻意理财，国库从 800 万两涨到第 6 年末 2600–3000 万两；朝局只从 55 缓降到 45 左右，从未接近危险线。0.41.1 做过的“财政有进有出”在被动玩法下基本不起作用。
- **改法**（调参数，不加系统）：
  1. 调高各卷常态军政开支（目前第一卷收 52、支 20，被动玩法每月净增约 30 万两），让“不管不顾”时国库每月只净增 0–10 万两。
  2. 国库超过 1500 万两时，户部每季自动呈一道“银两积压、请拨修河/赈济/边务”的折子，准奏即花掉一大笔并给出可见回报——给多余的钱一个**有意义的去处**，而不是新机制。
  3. 用现有 `scripts/v044-balance.mjs` 复跑，目标：被动玩法 6 年末国库在 600–1500 万两之间；积极理财可以更高。
- **验收**：把新平衡结果写入 `docs/施工/0.45-平衡验收.md`，附三组种子的曲线数据。

### C2 内帑形同虚设
- **现象**：赏一盒龙井只花 0.05 万两，最贵的点翠簪 0.35 万两；内帑每月固定 +4 万两，六年后积到 300 万两以上。玩家永远不需要考虑“赏不赏得起”。
- **改法**【作者已定：提高赏赐价格】：`data.js` 中 `GIFTS` 各项 `innerCost` 乘以 20（龙井 1 万两、点翠簪 7 万两，其余同比例），内帑月入维持 4 万两。赏赐面板每件礼物旁显示价格，内帑不足时按钮置灰并写明“内帑不足”。同时检查其他花内帑的地方（微服出游、南风馆、休养等），让它们与新价格处在同一量级。旧存档的内帑余额不变。
- **验收**：模拟中第 3 年内帑余额不超过 80 万两；每月按时辰全部用来赏赐时，内帑会在一年内吃紧。

### C3 情分“自动冷却”逼人刷
- **现象**：每月没接触到的核心人物（已见过、情分>30），一律 −1/−2。核心人物 9 位，但每月只有 3 个时辰 + 1 夜，最多照顾 4 人，其余人都在稳定下滑。模拟中除了被反复照顾的一两人，其余人六年后大多回落到 20–30，第三、四幕永远触发不了。这和“讨玩家开心”的定位冲突。
- **改法**：
  1. 冷却只对“情分 ≥ 45 且**连续 3 个月**未接触”的人生效，每次 −1。
  2. 月末报告里明确写出“谁在想你”（列出将要冷却的人），给玩家机会，而不是事后通知。
  3. 节庆、来访、书信算作接触。
- **验收**：模拟里平均分配行动时，第 4 年末至少 5 位核心人物 ≥ 45。

### C4 圣躬老化扣得太狠
- **现象**：第 5–6 年每月圣躬 −2、后宫 −1（一年 −24/−12），只能靠休养（占时辰）补，挤掉与人物相处的时间。
- **改法**：第 5–6 年改为每月圣躬 −1、每季后宫 −1；第 7 年后维持现状。

### C5 节庆占比过高
- **现象**：模拟中所有要事里节庆约占 17%（72 个月 26 次），而且节庆只要“两人能陪”就进入必做要事。
- **改法（作者已澄清）**：春节指「除夕守岁」，只有它与中秋必做；其余节庆含上元灯会均为当月可选卡，放在行动按钮上方、排在可选朝政卡前。不占要事、不挡行动、不耗时辰，原选人/全家/情分/吃醋效果保持。
- 未过节庆月末撤下，不罚、不顺延，跳过的节庆月份不计连续未联络；旧队列里的非必做节庆只在load中移卡，去重但不丢失，完成记录不改。
- **验收**：覆盖旧档迁移、不重复领取、不过节可月结；对比三组72个月节庆占全部实际完成要事的比例。

### C6 自由度掷骰
- 默认二档会在召见、下旨、夜里掷 d20。请确认界面在**结果出来之前**就告诉玩家“这次会掷骰、有哪些加成”；若当前只在结果里显示，改成行动前显示一行提示。（本轮未实测 AI 开启状态，请 Codex 用 mock 模型补一个浏览器截图验证。）

## D. 文本可读性（P1）

### D1 奏折正文大量套话
- **问题**：折匣里三道不同的折子，后半段完全相同：“臣已令属员封存原册，分别听取当事人供述。此事既关地方生计，也关官府信用，不敢只凭一面之词轻断。谨将勘报与经费清单随折呈览……绝不以空言塞责。”读起来像复制粘贴，正是作者说的“天书”问题。
- **改法**：每道折子只保留**一句话事由 + 一句话请求**（不超过 60 字），套话全部删除。例如：“广东属官考语年年优等，积案却有数百件。臣请重核考册。”需要的细节放进“查核”结果里。
- **验收**：在测试里断言折匣正文不超过 80 字，且任意两道折子不共享超过 15 字的相同子串。

### D2 折匣顶部说明
- 现有一大段规则说明（急灾、核实、经费、回报、值房、钱粮清欠……）。改成一行：“急灾排在最前。查核只查清楚，办事还要另拨银子。”其余规则放进“怎么玩”。

### D3 地理小错
- 「边堡待修」由**湖广巡抚**上奏，湖广不是边省。边务题只分配给西北、北疆、云贵、四川等边省。

### D4 月末报告可读性（作者追加）
- 全部数值标签的文字与底色对比度至少4.5:1；人物情分增加用绿色、减少用红色。
- “月底入账”中为0或对应系统未开启的项目不显示。
- 国库支出下列主要去向，分项必须与总数对上；旧档未记录的去向不得猜补。
- 验收：补零值项目不出现在报告文本里的测试，并覆盖390px截图 `output/playwright/v045/month-report.png`。

## E. 代码健康（P2，在 A–D 之后做）

1. **超长单行**：`engine.js`、`main.js` 等大量函数写成一行 1000–2600 字符（`main.js` 第 185、188 行分别 2619、2050 字符）。本轮只要求：**动到哪个函数，就把哪个函数按语句换行**；新加 `scripts/check-style.mjs`，对新增/修改的行检查长度 ≤160，并接入 `npm test`。
2. **全局当前存档**：`engine.js` 用模块级变量 `CUR` + `bind(s)` 让 `scene(id)` 找到存档。把 `scene` 改成 `scene(s,id)`，调用处逐一传入存档；保留一个兼容包装一版后删除。
3. **双份正文**：`content.js` 原稿 + `rewrite.js` 覆盖稿同时存在，改一处容易漏另一处。把 40 条改写稿合并回 `content.js`，删掉覆盖逻辑。
4. **README 过长**（30KB，大半是历代改动记录）：README 只留简介、运行、发布、当前版本改动；历代记录移到 `CHANGELOG.md`。
5. **BYOK 密钥**：线上版“记住此设备”会把 API 密钥明文存在 localStorage。保留功能，但勾选框旁加一行提示：“密钥会以明文保存在本浏览器。”
