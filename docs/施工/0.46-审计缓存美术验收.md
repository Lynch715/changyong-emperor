# 0.46.0 审计、缓存与美术验收

日期：2026-11-09；仓库 `Lynch715/changyong-emperor`，发布分支 `master`。

## 审计修复

1. 永久职位恢复只恢复职位，不再重复设置人物存活、出场和见面状态，避免后续明确去留被旧任命反复覆盖；任命历史不会重复堆积。
2. 地方数值改写接回 `regionChange`，照十省等权规则同步全国民心、朝局与小数累计。
3. 永久银两先记录实际收支，再记录「言出法随」的补足或收回。余额保持固定，军政和新政支出仍有账可查；月报新政金额按实际出账汇总。
4. 一档普通闲聊可以在不编造世界变化的情况下回应，只有召见/书信上下文允许空变化的 conversation 结果；命令入口仍拒绝空执行。自由对话继续累计次数和相关人物故事。
5. 等待模型时阻止界面动作切换存档或模式，避免旧请求在新局上落地。
6. 发布模块链统一带版本参数，避免只换入口却继续加载旧子模块；发布工作流加入完整回归检查。

## 缓存

召见的固定写作、输出和判定规则留在稳定 system 前缀；人物、数值、关系、记忆、骰面与玩家输入进入每次更新的上下文。世界事实也放入动态上下文，不再插入固定规则中。

以基线 `c6135bd` 同样的两位人物召见请求作比较，可重复的固定前缀由528字符增至1,037字符。这里是字符数，不是 token 或真实命中率。新前缀覆盖整段固定 system；测试核对变化后的健康、记忆、事实和骰面仍是最新值。

接收 DeepSeek 的 `prompt_cache_hit_tokens`、其他 Chat Completions 的 `prompt_tokens_details.cached_tokens` 和 Responses 的 `input_tokens_details.cached_tokens`。最近一次用量仅留在运行内存，可用 `aiUsage()` 检查，不写游戏存档或密钥配置。提供商未返回用量时显示为未知，不伪造百分比；每次仍实际调用模型，不缓存旧剧情回复。

实现依据：[DeepSeek 官方上下文缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)。前缀复用有助于服务端命中，实际是否命中及命中比例由服务商决定，本轮未调用付费模型测量。
