# 本地交付保护与恢复说明

2026年10月27日，S13-06。本地运行代码v0.13.0，正文快照15，首版内容为元年至二年。此说明不代表在线发布或三十年完整版完成。

## 先保全，再恢复

在平常游玩的浏览器、原协议／主机／端口打开游戏，进入“更多 → 设置与存档”，分别下载“导出当前存档”和“导出全部档案”。若正使用迁移副本，再下载“导出迁移包”和“下载原JSON”。将文件留在浏览器以外的磁盘目录，恢复前后各留一份，不用同名文件覆盖。导出只读取记录，不改写进度。

一套时间规则有八槽：自动档、上期／上周自动备份、恢复前备份、五手动槽。季度原档、普通周档、每个迁移副本各有独立八槽。普通“全部档案”只包含当前这一套八槽，不会自动汇总其他世界、其他副本或浏览器中的损坏留档。需要保护哪套，就在对应入口分别导出。

本轮没有读取或改动玩家正在游玩的浏览器来源；包里的历史验收JSON不是玩家当前存档。项目文件备份与浏览器存档备份必须分别保留。

## 三种入口与存档用途

| 类型 | 同一服务器中的入口 | 磁盘文件与恢复方法 |
| --- | --- | --- |
| 季度原档 | `/` | 普通单档在该入口“选择存档导入”，核对日期后“备份并载入”。 |
| 普通周档 | `/?world=weekly` | 普通周单档在周入口导入，不能用季度单档直接覆盖。 |
| 季度迁移副本 | `/?world=weekly&copy=<原JSON的SHA-256>`，通过“旧档接续”进入 | 跨设备／来源优先用完整迁移包；副本单档只可在对应副本入口恢复。 |

- 单档`changyong-save`：当前state，可恢复一份进度，不含其他七槽。
- 八槽集合`changyong-local-archive`：完整保全当前八槽的raw，包括空槽。当前UI不会将普通周制八槽集合整包回写；季度集合导入走的是选择一档复制迁移，也不等于恢复全部原槽。不要把“档案集合”误当作普通单档。
- 完整迁移包`changyong-migration-bundle`：保留精确季度原JSON及该副本八槽。空白来源可恢复整个副本；已有同一副本时只打开已有进度，不静默用旧包覆盖新进度。损坏副本的恢复页可显式恢复包内自动档，并保留其他本机槽。

五个手动槽保存会替换所选手动槽；先下载磁盘备份，再选择确实可用的槽。普通导入和手动载入会先把当前自动档写到单份“恢复前备份”，不会覆盖五手动槽；“恢复前备份”会随下次恢复轮替，不能代替磁盘备份。上一回合／上一周备份也会随推进轮替。

## 从八槽集合取回某一档

交付包附带离线工具，只读源集合，验证所选槽并写入一个**不存在的新文件**；它不访问浏览器、不修改原集合、不覆盖已有文件。先在编辑器查看集合的`records[].key`，用准确键名提取，例如：

```sh
node scripts/extract-archive-save.mjs "/绝对路径/周制全部档案.json" changyong-week-s02-manual-4 "/绝对路径/取回的第五槽.json"
```

季度前缀是`changyong-v12`，普通周档是`changyong-week-s02`，副本是`changyong-week-copy-<64位标识>`；后缀为`auto`、`previous`、`import-backup`或`manual-0`至`manual-4`。第五槽是`manual-4`，不是4号人物。工具原样保留该槽raw，不重新序列化正文。空槽、坏JSON、重复键、跨世界混合或副本身份不一致会拒绝输出。

取得单档后，在对应世界入口导入，先核对日期、国库和正文，再“备份并载入”。若要另行重建五手动槽，逐槽提取、导入、保存到相应手动槽；最后再导入原自动档作为当前进度。此操作可以恢复各槽的state，但保存时间、writeId、上一周及恢复前备份会变化，不能声称八槽raw完全相同。需要逐字节保全的原八槽集合应一直留在磁盘，当前没有普通八槽集合一键原样恢复按钮。

## 季度档复制迁移

1. 先在原季度入口导出单档和八槽集合，再到“设置与存档 → 旧档接续”。
2. 选择本机季度槽或旧JSON。预览日期、国库、承接余量、待办、旧约和新月账起点；取消不写原槽。
3. 选择“保留原档，创建副本”，下载完整迁移包后再进入副本。
4. 原季度八槽和普通周档仍在原入口；副本另有八槽。重复迁移完全相同的原JSON会打开已有副本，不重新初始化。

按原JSON字串识别副本；相同state但导出时间不同，可能得到不同标识。既有正文、流水、双方意愿和原封卷不重写；旧约可能需要重新协商，迁移本身不补发旧收入。已封季度卷保持原日期与只读封卷，不移到年末补结。

## 常见恢复情形

| 情形 | 处理 |
| --- | --- |
| 换端口、`localhost`与`127.0.0.1`互换后看似空档 | 回原地址和浏览器确认；存储按协议、主机、端口隔离。需迁移时从原来源导出，再在隔离新来源导入。不要在空地址以为原档已丢。 |
| 自动档损坏 | 停留恢复页，先下载原始记录。普通档可用“恢复前备份”；没有有效备份时，先完整保全坏记录，再在独立来源用磁盘单档恢复。不要清空浏览器。 |
| 副本自动档损坏或缺失 | 由恢复页选择对应副本手动档、恢复前备份、单档或迁移包。明确恢复会保留坏原始记录，季度原稿和其他副本不改。 |
| 一次导入选错档 | 先另行导出当前情况，再用事先的磁盘备份恢复；不要连续导入后假定单份“恢复前备份”仍是最早那份。 |
| 另一标签页更新、CAS冲突 | 当前操作未写入；先导出需要保留的信息，再“载入最新自动档”，核对后重新操作。不要反复提交过时操作。 |
| 存储已满、坏JSON、非法日期、跨规则／跨副本 | 保留原文件和当前原始导出，按错误说明换正确来源或有效备份。不手删正文、流水、意愿或已完成标记来通过校验。 |

普通单档上限为12,000,000字符，完整迁移包为120,000,000字符；超过限制保留原文件另行处理，不裁剪历史正文。

## 项目回退包与正式运行包

本地交付目录：`output/S13-06交付_20261027/`。

| 文件 | 用途 |
| --- | --- |
| `原项目回退_v0.13.0_S13-06前.tar.gz` | S13-06前2538文件项目快照，包括原设计、历史证据和旧输出；运行代码0.13.0／快照15。排除`.git`、依赖缓存、`.DS_Store`、真实`.env`及本轮新增输出。不是降回旧运行版本，也不包含浏览器实时存储。 |
| `本地交付_v0.13.0_S13-06.tar.gz` | 正式HTML、样式、服务器、src、全部运行资产、说明与离线恢复／包验证工具。不含测试fixture、QA页面、设计原稿、旧证据、真实密钥或玩家进度。 |
| `SHA256SUMS.txt` | 两个压缩包的SHA-256，用于核对磁盘文件是否完整。每个包内另有逐文件清单。 |

回退时先保全当前项目及浏览器导出，把包解到**新目录**核对，切勿直接覆盖正在施工的目录。示例（新目录必须不存在）：

```sh
shasum -a 256 "output/S13-06交付_20261027/原项目回退_v0.13.0_S13-06前.tar.gz"
python3 scripts/verify-source-package.py "output/S13-06交付_20261027/原项目回退_v0.13.0_S13-06前.tar.gz" --extract-to "/绝对路径/新建的回退核对目录"
```

该验证工具先校验全包路径、类型、数量、大小及逐文件SHA-256，全部通过后才向不存在的新目录解包；拒绝覆盖已有目录。与`SHA256SUMS.txt`比对全包摘要。在解出的`雍正爱恋`目录使用Node.js 22以上运行`npm start`，不需安装依赖。需要隔离时用`PORT=5251 npm start`，再访问`http://127.0.0.1:5251/?world=weekly`。这会是独立浏览器来源，必须显式导入备份才能看见原进度。

正式运行入口只有`index.html`／`src/app.js`和`server.mjs`。`npm start`仅监听127.0.0.1，静态文件仅开放根HTML／CSS及src／assets，不提供脚本目录、原稿、回退包或QA fixture。项目保留的`serve-*-fixture.mjs`只是旧验收证据配套工具，未删除历史脚本，也未放进运行包；交付时不要启动它们。本地验收和进度更新不构成发布授权。
